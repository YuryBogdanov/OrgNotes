# Panopticon

Нативное macOS-приложение для заметок, задач и агенды поверх обычных `.org`-файлов.
Tauri 2 + Svelte 5 + CodeMirror 6. Репозиторий — OrgNotes (рабочее название), само приложение — Panopticon.

## Запуск

```bash
npm install
npx tauri dev            # нативное окно
npm run dev              # только веб-версия на http://localhost:1420
```

Нужны Node.js и Rust (`brew install node rust`).

Папка с заметками выбирается при первом запуске (экран приветствия) и запоминается вместе с закладкой macOS, так
что переименование или перенос папки её не теряет. Для разработки её можно задать переменной `ORG_DIR`.

Собрать `Panopticon.app`: `npx tauri build --bundles app`. Иконка собирается из `src-tauri/icons/source.png`
(квадрат дизайнера) → `app-icon.png` (шаблон macOS: скруглённый квадрат 824 на 1024) → `npx tauri icon`.

Релиз: `scripts/release-mac.sh` собирает приложение (Apple Silicon, ad-hoc подпись всего бандла) и кладёт архив в
`dist-release/Panopticon-<версия>-macos-arm64.zip`; его прикладываем к релизу на GitHub. Подписи Developer ID и
нотаризации нет, поэтому при первом запуске на другом Mac: «Системные настройки → Конфиденциальность и безопасность →
Всё равно открыть» (или `xattr -dr com.apple.quarantine /Applications/Panopticon.app`).

```bash
ORG_DIR=~/notes npx tauri dev
```

## Панели и вкладки

Окно держит одну или две панели редактора рядом; у каждой свои вкладки (файл или агенда). Активная панель одна
(акцентная полоска сверху), клик в любом её месте делает её активной.

- Тулбар, группа «Открыть в панели»: «Второй редактор» (копия текущей вкладки), «Агенда», «Календарь» (пока
  выключен). Нажатая кнопка показывает, что открыто во второй панели. Повторное нажатие «Второй редактор» закрывает
  вторую панель, её вкладки переходят в конец первой; повторное «Агенда» закрывает вкладку агенды.
- Крестика у панели нет: панель закрывается вместе со своей последней вкладкой (оставшаяся становится активной),
  кнопкой в тулбаре или «Вид → Закрыть панель» ⌃⌘W (вкладки переходят в соседнюю, ничего не теряется).
- Агенда: клик или ↩ на задаче открывает файл в соседней панели на её заголовке, фокус остаётся в агенде; если
  соседней нет, она появляется **слева** (агенда остаётся справа). ⌥↩ — в той же панели, двойной клик — с
  переходом в файл. Внизу файла «Открыто из агенды: …», пока каретка на этом заголовке.
- Меню «Вид»: «Разделить вправо» ⌘\, «Поменять панели местами» ⇧⌃⌘→, «Оставить одну панель» ⇧⌘\,
  ⌥⌘← / ⌥⌘→ — перейти в левую или правую панель. ⌘W закрывает вкладку, средняя кнопка мыши тоже.
- Узкое окно: сначала прячется инспектор, потом навигатор, панель не уже 320 pt, затем вторая панель становится
  вкладками первой. Границу между панелями можно тянуть, двойной клик возвращает 50/50.
- Один файл в двух редакторах — один документ: правка видна сразу в обоих, каретки свои.
- Раскладка (панели, вкладки, каретки, пропорция) восстанавливается после перезапуска.

### Вкладки

- Правый клик (или ⌃-клик) по вкладке: «Закрыть» ⌘W, «Закрыть остальные» ⌥⌘W, «Переместить в соседний
  редактор» ⌃⌘→/←, «Продублировать в соседнем редакторе» ⌥⌃⌘→/←, для файла ещё «Показать в навигаторе» ⇧⌘J и
  «Скопировать путь» ⌥⌘C. Команды относятся к вкладке под курсором, а не к активной. С одной панелью
  перемещение и дублирование недоступны; уже открытый в соседней панели файл не открывается второй раз.
- Двойной клик по пустому месту ряда вкладок — новая «Без названия» с кареткой в пустом редакторе. Её текст
  живёт только в памяти, на диске файл появляется после «Сохранить как…» (⌘S или кнопка внизу): имя берётся из
  первого заголовка, папка — из файла соседней панели или последняя выбранная; можно создать папку. Если файл
  уже есть, спросит «Заменить».
- Вкладки не уже 110 pt; если не помещаются, ряд прокручивается (трекпад, колесо), края затухают, справа
  появляется «⌵» со списком всех вкладок. Через секунду над вкладкой файла — полный путь на диске. Новая вкладка
  без свободного места — «Файл → Новая вкладка» ⌘T.
- Имена файлов везде без «.org» (вкладки, путь, строка состояния, агенда); расширение остаётся в «Скопировать путь»,
  в подсказке и в тексте файлов. «Сохранить как…» само добавляет «.org», если его не ввели.
- В узкой панели второстепенное уходит целиком: у пустой вкладки сначала подсказка, потом ⌘S; в строке состояния
  путь теряет папки с начала («…/Рост/Сергей Белов»), потом уходят UTF-8 и Org.
- Закрытие с несохранённым текстом (⌘W, «Закрыть остальные», ⌘Q, ⌘⇧W, красная кнопка) показывает один лист:
  «Сохранить» (Return), «Не сохранять» (⌘D), «Отмена» (Esc, ⌘.). Файлы сохраняются сами через полсекунды после
  правки, поэтому файл попадает в лист, только если запись не удалась; не дописанная запись уходит при закрытии
  молча. Новая заметка с текстом — всегда (имя — первая строка без звёздочек); пробелы не считаются. Для нескольких
  вкладок — список и «Сохранить всё»: файлы пишутся сразу, для заметок по очереди «Сохранить как», отмена или ошибка
  на любом шаге ничего не закрывает. Файл, открытый в обеих панелях, спрашивается только при закрытии последней
  вкладки.

## Первый запуск и рабочая папка

- Нет папки — экран «Добро пожаловать в Panopticon»: «Выбрать папку…» (Return) или «Создать новую папку…».
  Выбранная папка показывается на экране «Папка найдена»: сколько org-файлов, папок и других файлов (скрытые
  папки вроде `.git`, служебные файлы Emacs и ссылки не учитываются); для домашней папки, диска или больше
  10 000 файлов — мягкое предупреждение. «Открыть» запоминает папку.
- Пустая папка — «Создайте первый файл» (⇧⌘N), «Показать в Finder»; первый же org-файл, хоть из Emacs,
  убирает это состояние.
- Папка недоступна при запуске — экран с путём, «Повторить» и «Выбрать другую папку…»; проверка повторяется
  сама. Пропала во время работы — вкладки и текст остаются, в навигаторе плашка «Папка недоступна».
- Сменить папку: «Файл → Открыть другую папку…» или «Настройки → Основные → Изменить…»; сначала вопрос о
  несохранённом, отмена на любом шаге ничего не меняет.
- Закрытие окна (красная кнопка, ⌘⇧W) прячет его, приложение остаётся в Dock — щелчок по иконке возвращает
  окно с вкладками и текстом. Выход — ⌘Q (с вопросом о несохранённом, так же из Dock).

## Файл изменился на диске

Приложение никогда не теряет чей-либо текст без явного решения. Файлы проверяются по событиям папки, при возврате
в окно и перед каждой записью; «тронутый» файл с тем же текстом ничего не вызывает.
- Вкладка без правок обновляется сама: курсор на той же строке и колонке, плашка «обновлён с диска» на 4 секунды,
  ⌘Z не возвращает старый текст.
- Правки есть (запись ещё не ушла или не удалась), а файл стал другим: лист «Файл изменён другой программой» с
  временем обеих версий. Return — «Сравнить…» (построчно, «−»/«+»), «Загрузить с диска» (⌘Z вернёт ваши правки),
  «Оставить мою версию» (перезапишет диск). Esc откладывает: автосохранение ждёт, вопрос вернётся при ⌘S,
  закрытии вкладки или возврате в окно. Один файл в двух панелях — один вопрос.
- Файл перемещён в пределах папки (тот же текст появился по новому пути) — вкладка тихо переходит на новый путь.
  Удалён — вкладка остаётся (курсив, «Файла нет на диске»), ⌘S создаст файл заново; с правками — лист
  «Сохранить как… / Оставить открытой / Закрыть без сохранения».

## Навигатор и структура файла

Навигатор показывает только папки и файлы: шеврон есть у непустых папок, у файлов его нет, имена одного уровня
выровнены по одной линии. Щелчок по файлу открывает его, а клавиатура остаётся в навигаторе: ←/→ сворачивают и раскрывают папки, ↑↓ ходят по строкам, как в Finder, ↩ переводит в редактор. Заголовки файлов
в навигаторе можно включить в «Настройки → Основные» (хранится на этом Mac): тогда у файла с заголовками шеврон
виден, когда файл раскрыт или под курсором мыши.

Структура файла — в инспекторе, вкладка «Структура» (её выбор запоминается): дерево заголовков активного редактора,
фильтр по тексту, «Все / Только задачи», свёрнутая ветка показывает счётчик задач. Подсвечен заголовок, где стоит
курсор. Клик или ↑↓ переводят курсор в редакторе, фокус остаётся в списке; ↩ или двойной клик — в редактор.
В палитре то же по «#» и команда «Показать структуру файла».

## Строка пути

Путь до файла в тулбаре — сегменты с меню, как в Xcode: у папки — папки того же уровня (у каждой подменю с её
содержимым), у файла — файлы его папки, текущий отмечен галочкой. ⌃⌘J («Вид → Строка пути») переводит туда
клавиатуру: ←/→, Home/End — сегменты, ↓ или ↩ — меню; в меню ↑/↓, → открывает папку, ← закрывает, на верхнем
уровне ←/→ — меню соседнего сегмента; набор текста фильтрует (подстрока, без регистра, «ё» = «е», любая
раскладка); Esc — на уровень назад, последний — в текст. ↩ открывает файл в активной панели, ⌥↩ — в соседней;
вкладка с несохранённым текстом остаётся, курсор встаёт туда, где был в этом файле.

## Командная палитра

⇧⌘P (или «Вид → Командная палитра») — команды и файлы с клавиатуры, как `M-x` в Emacs. Поиск нечёткий: «сф» найдёт
«Создать файл…», регистр и «ё/е» не важны. Если курсор в заголовке, сверху его плашка и группа «К ЗАГОЛОВКУ»:
сменить статус, запланировать, дедлайн, теги, перенести в другой файл. «ОБЩИЕ» — создать файл (⇧⌘N) или папку,
новая задача в конец файла, перейти к файлу (⇧⌘O). С запросом ниже появляются файлы. «#» в начале — переход
к заголовку текущего файла («№» работает так же — это Shift+3 в русской раскладке). Команды с «…» продолжаются в том же окне: список статусов, дата словами («завтра»,
«пт», «14 окт», «+3д»), теги через пробел, выбор файла, имя. Esc закрывает всё, фокус возвращается к курсору.
Часто используемые команды поднимаются выше (история хранится на этом Mac).

## Хоткеи редактора (как в Org)

| Клавиши | Действие |
|---|---|
| ⌥↩ | Новый заголовок того же уровня (до первого заголовка — 1-го уровня). В начале заголовка — выше; в конце свёрнутого — после его поддерева; в середине строки — разрезает её; на пустой строке — превращает её в заголовок |
| ⌥⇧↩ | То же, но сразу с первым открытым статусом (`TODO`) |
| ⌥← / ⌥→ | Поднять / опустить заголовок на уровень вместе со всем поддеревом (⌥⇧← / ⌥⇧→ — то же) |
| ⌥↑ / ⌥↓ | Поменять поддерево местами с предыдущим / следующим соседом того же уровня; курсор остаётся на заголовке |
| ⇧↑ / ⇧↓ | Приоритет: нет → B, ⇧↑ к A, ⇧↓ к C, по кругу |
| ⇧→ / ⇧← | Статус внутри workflow заголовка. Нет статуса — первый статус первого workflow (в любую сторону). → после последнего статуса снимает статус; ← на первом статусе любого workflow снимает статус |
| ⌃⇧→ / ⌃⇧← | Перейти на первый статус следующего / предыдущего workflow. Нет статуса — первый статус первого workflow. → с последнего workflow и ← с первого снимают статус |
| Tab | Свернуть / развернуть заголовок под курсором |
| ⇧Tab | Всё свёрнуто → открыт 1-й уровень → 2-й → … → всё открыто → снова свёрнуто |

⌥-стрелки и ⇧-стрелки (в том числе ⇧←/→ и ⌃⇧←/→ для статусов) работают как команды структуры **только на строке заголовка**; в тексте заметки они остаются
обычными (перемещение по словам, выделение), как в Org на Mac. Одна команда — один шаг отмены (⌘Z).

## Настройки проекта и workflow статусов

Настройки живут рядом с заметками: `<папка заметок>/.orgnotes/config.json`. Это файл проекта, его можно коммитить в git:
у домашних и рабочих заметок свои статусы, и они не смешиваются. Скрытая папка не показывается как заметки.

```json
{
  "version": 1,
  "workflows": [
    { "name": "Задачи", "states": [
      { "name": "TODO", "color": "red" },
      { "name": "IN PROGRESS", "color": "blue" },
      { "name": "DONE", "done": true, "color": "green" } ] },
    { "name": "Встречи", "states": [
      { "name": "MEETING" }, { "name": "FINISHED", "done": true } ] }
  ]
}
```

- Первый статус workflow — стартовый. У заголовка без статуса workflow первый в списке.
- Имя статуса — ключевое слово Org: пробелы заменяются на `-` (`IN PROGRESS` → `IN-PROGRESS`).
- Статус принадлежит одному workflow: при повторе побеждает первое объявление, остальное пропускается с предупреждением
  (Org не может определить, по какой последовательности «крутить» повторяющееся слово).
- `#+TODO:` в файле остаётся и **переопределяет** проектный конфиг для этого файла. Приложение его само не пишет.
- Цвета: `gray red orange green teal blue purple pink` или `#rrggbb` (тёмный вариант считается сам по контрасту 4.5:1).
  Состояние новой задачи: `"initial": "TODO"` у набора. Файла нет — работает встроенный набор TODO NEXT WAIT | DONE CANCELLED.
- Изменения конфига подхватываются без перезапуска.
- `behavior`: `closedTimestamp` (по умолчанию `true`, писать `CLOSED:`) и `logbook` (по умолчанию `false`, вести
  `- State "DONE" from "TODO" [..]` в `:LOGBOOK:`). Действуют на весь проект.

Редактировать это удобнее в **Настройки → Статусы** (⌘, или шестерёнка в тулбаре; открывается отдельным окном):

- таблица: цвет (пикер из 8 цветов с превью на светлой и тёмной теме и «Другой цвет…»), название (только чтение,
  выводится из слова), слово «В ФАЙЛЕ» (единственное редактируемое поле: заглавные, пробел → дефис, до 24 символов,
  без `( ) | @ ! /`), клавиша (чип: первая буква слова, при совпадении следующая свободная);
- порядок строк перетаскиванием или ⌥↑ / ⌥↓ на строке; порядок наборов перетаскиванием в левом списке;
- «+ Состояние» создаёт серую строку с курсором в «В ФАЙЛЕ»; Return подтверждает, Esc отменяет;
- «Состояние новой задачи» — какой открытый статус получает новая задача набора (`initial` в конфиге);
- удаление используемого статуса: подтверждение с числом заголовков; переименование используемого: «Заменить в
  файлах» / «Только в настройках» / «Отмена»;
- изменения применяются сразу, пока нет ошибок; неизвестные поля конфига сохраняются.

## Файлы и папки

В навигаторе: «+» (или ⌘N) создаёт файл или папку, правый клик даёт переименование, перемещение (диалог или перетаскивание),
«Показать в Finder» и удаление. Удаление только в Корзину (восстановимо). Имена: без `/` и `:`, без точки в начале;
расширение `.org` добавляется само. При переименовании и перемещении относительные ссылки `[[file:…]]` во всех заметках
пересчитываются, несохранённые правки сохраняются до операции.

## Ссылки

Поддерживаются `[[file:путь.org::*Заголовок]]`, `[[id:…]]` (по `:ID:`), `[[#custom]]`, `[[*Заголовок]]`, http(s) и mailto.
В редакторе показывается только описание ссылки; ⌘-клик или ⌘↩ переходит по ней, ⌘[ возвращает назад.
В инспекторе видны ссылки из текущего заголовка и обратные ссылки на него.

## Тесты

```bash
npm test                 # парсер и правки (vitest)
(cd src-tauri && cargo test)   # безопасное сохранение файлов
npm run e2e              # редактор в WebKit (движок WKWebView) с имитацией Tauri-бэкенда
```

Для e2e один раз: `npx playwright install webkit`. Тесты используют уже запущенный dev-сервер на порту 1420
(например, `tauri dev`) или поднимают свой; порт задаётся переменной `E2E_PORT`.

## Принципы

- `.org`-файлы остаются источником истины, формат 1:1 с Emacs.
- Правки делаются патчами по тексту, документ не пересериализуется из дерева.

# Org

Нативное macOS-приложение для заметок, задач и агенды поверх обычных `.org`-файлов.
Прототип: Tauri 2 + Svelte 5 + CodeMirror 6.

## Запуск

```bash
npm install
npx tauri dev            # нативное окно
npm run dev              # только веб-версия на http://localhost:1420
```

Нужны Node.js и Rust (`brew install node rust`).

Папка с заметками: переменная `ORG_DIR`, по умолчанию `sample-notes/`.

```bash
ORG_DIR=~/notes npx tauri dev
```

## Хоткеи редактора (как в Org)

| Клавиши | Действие |
|---|---|
| ⌥↩ | Новый заголовок того же уровня (до первого заголовка — 1-го уровня). В начале заголовка — выше; в конце свёрнутого — после его поддерева; в середине строки — разрезает её; на пустой строке — превращает её в заголовок |
| ⌥⇧↩ | То же, но сразу с первым открытым статусом (`TODO`) |
| ⌥← / ⌥→ | Поднять / опустить заголовок на уровень вместе со всем поддеревом (⌥⇧← / ⌥⇧→ — то же) |
| ⌥↑ / ⌥↓ | Поменять поддерево местами с предыдущим / следующим соседом того же уровня; курсор остаётся на заголовке |
| ⇧↑ / ⇧↓ | Приоритет: нет → B, ⇧↑ к A, ⇧↓ к C, по кругу |
| Tab | Свернуть / развернуть заголовок под курсором |
| ⇧Tab | Всё свёрнуто → открыт 1-й уровень → 2-й → … → всё открыто → снова свёрнуто |

⌥-стрелки и ⇧-стрелки работают как команды структуры **только на строке заголовка**; в тексте заметки они остаются
обычными (перемещение по словам, выделение), как в Org на Mac. Одна команда — один шаг отмены (⌘Z).

## Настройки проекта и workflow статусов

Настройки живут рядом с заметками: `<папка заметок>/.orgnotes/config.json`. Это файл проекта, его можно коммитить в git:
у домашних и рабочих заметок свои статусы, и они не смешиваются. Скрытая папка не показывается как заметки.

```json
{
  "version": 1,
  "workflows": [
    { "name": "Задачи", "states": [
      { "name": "TODO", "color": "red" },
      { "name": "IN PROGRESS", "color": "blue" },
      { "name": "DONE", "done": true, "color": "green" } ] },
    { "name": "Встречи", "states": [
      { "name": "MEETING" }, { "name": "FINISHED", "done": true } ] }
  ]
}
```

- Первый статус workflow — стартовый. У заголовка без статуса workflow первый в списке.
- Имя статуса — ключевое слово Org: пробелы заменяются на `-` (`IN PROGRESS` → `IN-PROGRESS`).
- Статус принадлежит одному workflow: при повторе побеждает первое объявление, остальное пропускается с предупреждением
  (Org не может определить, по какой последовательности «крутить» повторяющееся слово).
- `#+TODO:` в файле остаётся и **переопределяет** проектный конфиг для этого файла. Приложение его само не пишет.
- Цвета: `gray red blue orange green purple`. Файла нет — работает встроенный набор TODO NEXT WAIT | DONE CANCELLED.
- Изменения конфига подхватываются без перезапуска.

## Файлы и папки

В навигаторе: «+» (или ⌘N) создаёт файл или папку, правый клик даёт переименование, перемещение (диалог или перетаскивание),
«Показать в Finder» и удаление. Удаление только в Корзину (восстановимо). Имена: без `/` и `:`, без точки в начале;
расширение `.org` добавляется само. При переименовании и перемещении относительные ссылки `[[file:…]]` во всех заметках
пересчитываются, несохранённые правки сохраняются до операции.

## Ссылки

Поддерживаются `[[file:путь.org::*Заголовок]]`, `[[id:…]]` (по `:ID:`), `[[#custom]]`, `[[*Заголовок]]`, http(s) и mailto.
В редакторе показывается только описание ссылки; ⌘-клик или ⌘↩ переходит по ней, ⌘[ возвращает назад.
В инспекторе видны ссылки из текущего заголовка и обратные ссылки на него.

## Тесты

```bash
npm test                 # парсер и правки (vitest)
(cd src-tauri && cargo test)   # безопасное сохранение файлов
npm run e2e              # редактор в WebKit (движок WKWebView) с имитацией Tauri-бэкенда
```

Для e2e один раз: `npx playwright install webkit`. Тесты используют уже запущенный dev-сервер на порту 1420
(например, `tauri dev`) или поднимают свой; порт задаётся переменной `E2E_PORT`.

## Принципы

- `.org`-файлы остаются источником истины, формат 1:1 с Emacs.
- Правки делаются патчами по тексту, документ не пересериализуется из дерева.

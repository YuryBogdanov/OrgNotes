# ТЗ: файл изменился на диске

2026-10-11 · Yury Bogdanov

## Контекст

Файлы заметок можно одновременно редактировать в приложении и в другой программе: в Emacs, через git, синхронизацию облака. Без явного поведения в этом случае легко потерять правки: приложение перезапишет чужую версию или покажет устаревший текст. Правило всего одно: **приложение никогда не теряет чей-либо текст без явного решения пользователя**.

Если во вкладке нет несохранённых правок, файл обновляется с диска тихо. Если правки есть — показывается диалог выбора версии с возможностью сравнить. Для удалённого или перемещённого файла — отдельный сценарий.

Макеты на доске, раздел «Файл изменился на диске», каждый в светлой и тёмной теме: «Конфликт с диском — выбор версии», «Сравнение версий», «Файл удалён на диске», «Обновлено с диска (без правок)». Диалоги делаются тем же листом macOS (sheet), что и диалог закрытия несохранённой вкладки.

## 1. Как приложение узнаёт об изменениях

**Три момента проверки.** (1) По событиям файловой системы для всех открытых файлов и рабочей папки. (2) Каждый раз, когда приложение снова становится активным — проверяются все открытые файлы на случай пропущенных событий. (3) Перед каждым сохранением файла. Третий момент обязателен: даже если событие не пришло, приложение не перезаписывает файл, который изменился после последнего чтения или записи.

**Что считается изменением.** Сравнивается содержимое файла (хэш) и время изменения. Если дата изменилась, а текст тот же (например, файл «тачнули»), ничего не показывается.

**Свои записи.** Всякая запись файла самим приложением игнорируется как изменение; после записи запоминается новая «опорная» версия.

**Служебные файлы Emacs** (`.#имя` — блокировка, `#имя#` — автосохранение, `имя~` — резервная копия) игнорируются: не показываются в навигаторе и не вызывают реакции. Правило нужно подтвердить по реальной работе Emacs у пользователя.

**Запись через замену файла.** Многие программы (в том числе Emacs и git) записывают файл новым файлом с переименованием. Приложение следит за путём, а не за конкретным открытым дескриптором, иначе такие замены не будут замечены.

## 2. Вкладка без правок: тихое обновление

Если во вкладке нет несохранённых правок, текст молча заменяется версией с диска. Курсор остаётся на той же строке и в той же колонке (если строки больше нет — на последней), положение прокрутки сохраняется. Инспектор, панель «Структура», заголовки в навигаторе и агенды пересчитываются по новому тексту.

**Уведомление.** Поверх редактора, внизу по центру, небольшая плашка ««work» обновлён с диска: файл изменила другая программа» с иконкой обновления. Плашка не забирает фокус, не блокирует ввод и исчезает сама через 4 секунды. Если за это время обновилось несколько файлов, вместо нескольких плашек показывается одна: «Обновлено с диска: N файлов». Для неактивных вкладок плашка не показывается: они обновляются без уведомления.

**Что не делается.** История отмен (⌘Z) после тихого обновления сбрасывается: отмена не должна материализовать старый текст поверх нового файла. Макет: «Обновлено с диска (без правок)».

## 3. Вкладка с правками: диалог выбора версии

**Когда показывается.** Если в вкладке есть несохранённые правки и файл на диске стал другим. Диалог появляется, когда приложение активно и эта вкладка видна в одной из панелей. Если файл изменился, пока приложение в фоне или вкладка была не видна, диалог покажется в момент, когда она станет видна. Неразрешённый конфликт отмечается на вкладке её точкой «есть правки», как и обычные несохранённые правки.

**Вид.** Лист окна шириной 440 pt, тем же оформлением, что диалог закрытия вкладки. Заголовок: «Файл «work» изменён другой программой». Пояснение объясняет последствия обеих веток выбора. Ниже — две строки: «Моя версия» с временем последней правки и «Версия на диске» с временем изменения файла; у моей версии — оранжевая точка «есть правки».

**Кнопки** (слева направо):

- «Сравнить…» (слева) — открывает сравнение версий (раздел 4), решения не принимает.
- «Загрузить с диска» — текст вкладки заменяется версией с диска, мои правки пропадают, вкладка становится «без правок». Курсор сохраняется по правилу раздела 2.
- «Оставить мою версию» (главная, срабатывает по Return) — текст вкладки не меняется, вкладка остаётся «с правками». Текущая версия на диске запоминается как принятая, диалог не появится снова, пока файл не изменится ещё раз; при следующем сохранении файл на диске перезаписывается без повторного вопроса.

**Esc** закрывает лист без решения: вкладка остаётся в состоянии конфликта, диалог появится снова при ⌘S, при закрытии вкладки и при следующем возврате в приложение. Кнопки «Отмена» в этом диалоге нет: отмена есть только как «отложить» по Esc.

**Макет:** «Конфликт с диском — выбор версии».

## 4. Сравнение версий

Режим чтения в том же листе (ширина 720 pt, заменяет диалог выбора). Редактировать текст здесь нельзя.

**Содержимое.** Заголовок «Сравнение версий «work»» и число отличий, только числом фрагментов (групп подряд идущих правок), а не строк. Легенда: красным — строки с диска, которые пропадут, если оставить мою версию; зелёным — строки из моей версии, которые перезапишут диск. Цвет не единственный признак: каждая строка ещё помечена знаком «−» или «+».

**Строки.** Моноширинный шрифт, 22 pt на строку, слева номер строки. Для «−» — номер в файле на диске, для «+» и неизменённых — в моей версии. Вокруг каждого фрагмента показываются три неизменённые строки контекста; длинные неизменённые участки сворачиваются в строку «… N строк без изменений». Длинная строка обрезается многоточием, вся строка доступна в подсказке. Длинный список прокручивается внутри листа.

**Кнопки.** «Назад» возвращает к диалогу выбора (он же Esc); «Загрузить с диска» и «Оставить мою версию» работают так же, как в диалоге выбора (раздел 3).

**Если файл на диске ещё раз изменился** пока лист открыт, сравнение и время в диалоге обновляются; решение применяется к последней версии.

**Макет:** «Сравнение версий».

## 5. Файл удалён или перемещён

**Переименование и перемещение.** Если приложение может надёжно понять, что файл просто переименован или перенесён в пределах рабочей папки, вкладка тихо переходит на новый путь (название вкладки и путь в тулбаре обновляются), диалога нет. Если надёжно распознать это нельзя, файл считается удалённым.

**Вкладка с правками.** Показывается лист «Файл «work» удалён или перемещён»: файла больше нет по прежнему пути, а в вкладке есть несохранённые изменения. Кнопки:

- «Сохранить как…» (главная) — открывает «Сохранить как» с прежним именем; папка — прежняя, если она есть, иначе рабочая папка. После сохранения вкладка указывает на новый файл.
- «Оставить открытой» — вкладка остаётся с текстом, диалог закрывается. Вкладка сохраняет отметку «файла нет на диске» (внешний вид отметки не нарисован, см. открытые вопросы); ⌘S создаст файл заново по тому же пути.
- «Закрыть без сохранения» (слева) — вкладка закрывается, текст теряется.

Esc тут, как и в диалоге выбора, «отложить»: так же, как «Оставить открытой».

**Вкладка без правок.** Диалога нет: вкладка остаётся открытой, текст не теряется, появляется та же отметка «файла нет на диске». Закрытие вкладки — без вопросов.

**Навигатор.** Файл исчезает из дерева, панель «Структура» показывает текст из вкладки (он пока живёт только там).

**Макет:** «Файл удалён на диске».

## 6. Особые случаи

**Один файл в двух панелях.** Текст один, поэтому диалог один: он показывается в активной панели, решение применяется к обеим.

**Много файлов сразу** (например, после `git pull`). Вкладки без правок обновляются тихо (одна общая плашка, раздел 2). Для вкладок с правками диалоги выстраиваются в очередь, по одному за раз: сначала для активной вкладки, остальные — когда вкладка станет видна.

**Сохранение при конфликте.** ⌘S во вкладке, где конфликт ещё не разрешён, сначала показывает диалог выбора, файл не записывается. Та же проверка работает в «Сохранить» и «Сохранить всё». Даже если событие не пришло и приложение узнаёт об изменении только в момент записи, диалог показывается до записи.

**Закрытие вкладки.** При «Сохранить» в диалоге закрытия несохранённой вкладки с неразрешённым конфликтом сначала показывается диалог выбора версии, потом закрытие. «Не сохранять» закрывает вкладку без дополнительных вопросов.

**Повторные изменения.** Если файл снова изменился после того, как пользователь выбрал «Оставить мою версию», начинается новый конфликт с новым временем.

**Файлы, которые не открыты.** Диалоги не показываются для файлов, которые в приложении не открыты: навигатор просто обновляет дерево и заголовки.

## Открытые вопросы и приёмка

**Открытые вопросы**

- Кнопка по умолчанию (Return) — «Оставить мою версию», так записано в макете. После неё при следующем сохранении файл, который писала другая программа, перезаписывается. Нужно подтвердить, что это неопасно для вашего сценария с Emacs, или сделать главной «Сравнить…».
- Возврат «Загрузить с диска» через ⌘Z (чтобы вернуть свои правки после ошибочного выбора) в ТЗ не заложен. Нужно решить, нужен ли он в первой версии.
- Внешний вид отметки на вкладке удалённого файла («файла нет на диске») не нарисован. Предлагаю курсивное название вкладки и подсказку при наведении.
- Распознавание переименования файла: насколько надёжно удастся отследить, решает разработчик. Если ненадёжно, можно всегда считать файл удалённым: текст всё равно не потеряется.
- Служебные файлы Emacs (раздел 1) игнорируются — проверить на вашей настройке Emacs.

**Приёмка**

- Файл в вкладке без правок изменили в Emacs: текст обновился сам, курсор на месте, появилась плашка на 4 секунды, ввод не блокируется.
- После тихого обновления ⌘Z не возвращает старый текст.
- Файл «тачнули» без изменения текста: ничего не показывается.
- Файл в вкладке с правками изменили в Emacs: появляется диалог с тремя кнопками и двумя строками с временем.
- «Сравнить…» показывает отличия с цветом и знаками «−» и «+», «Назад» возвращает к диалогу.
- «Загрузить с диска» заменяет текст и снимает отметку «есть правки»; «Оставить мою версию» не меняет текст и не показывает диалог снова, пока файл не изменится ещё раз.
- ⌘S на неразрешённом конфликте не перезаписывает файл, а показывает диалог.
- Файл удалён: лист с тремя кнопками (для вкладки с правками), текст не теряется ни при каком выборе, кроме «Закрыть без сохранения».
- Светлая и тёмная темы: цвета из токенов, разница не только цветом.

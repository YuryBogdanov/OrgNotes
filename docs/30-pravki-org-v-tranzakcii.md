## Зачем

Плагин «Цели квартала» правит свои файлы через `tx.update(path, fn)`: он берёт текст файла целиком и возвращает новый. Ядро не видит, что именно поменялось. Поэтому такие правки нельзя проверить, объединить с соседними и потом выполнить в изоляции (API v2).

Правильно, чтобы плагин описывал правку операциями Org-уровня, а ядро применяло их. Задача — дать в API операции, которых целям не хватает, и перевести цели на них.

**Для пользователя ничего не меняется:** файлы получаются те же, байт в байт. Это проверяют e2e целей — их сценарии не меняются.

## 1. Чем цели правят файлы сейчас

| Действие | Сейчас | На операциях |
|---|---|---|
| Новая цель | `insertGoal`: строки цели под кварталом; если квартала нет — он создаётся на своём месте (новые кварталы выше старых) | `ensureChild(источник, «Квартал Q4 2026», { before: более старый квартал })` → `insertHeading({ under: квартал, position: 'last' }, текст цели)` |
| Отметка | `addMark`: строка `- [дата] текст` в «Отметки» по порядку дат; если «Отметок» нет — они создаются | `ensureChild(цель, «Отметки»)` → `body(отметки)` → `replaceBody(отметки, тело с новой строкой на месте)` |
| Цель в другой квартал | `moveGoal` | `ensureChild(источник, квартал)` → `move(цель, { under: квартал })` |
| Перенос незакрытых | `carryOver`: перенос каждой цели, срок внутри старого квартала → последний день нового, отметка «Перенесена из …» | то же, что выше, плюс `setPlanning(DEADLINE)`; всё одной транзакцией |
| Новый источник | `addSourceHeading`: `* Квартальные задачи` в конце файла | `insertHeading({ file, position: 'end' }, '* Квартальные задачи')` |
| Статус и срок цели | уже `setStatus`, `setPlanning` | без изменений |

## 2. Что добавляем в `Tx` (API 1.3)

Все операции идут по порядку в памяти транзакции: следующая видит результат предыдущей.

- **`insertHeading(at, org): HeadingRef | null`** — теперь возвращает ссылку на вставленный заголовок. Новое место: `{ under, before: HeadingRef }` — перед указанным подзаголовком.
- **`ensureChild(under, title, at?): HeadingRef | null`** — прямой подзаголовок с таким названием (без учёта регистра и пробелов по краям); если его нет, создаётся `last` или `{ before }`.
- **Чтение внутри транзакции:**
  - `heading(ref): HeadingInfo | null`;
  - `children(ref): HeadingInfo[]` — прямые подзаголовки;
  - `body(ref): string` — текст под заголовком до первого подзаголовка, как его меняет `replaceBody`.
- **`move(ref, { under })`** работает и с заголовком, созданным в той же транзакции. Уже так, проверим тестом.

`tx.update` остаётся в API как запасной путь для плагинов со своей структурой в файле. В инструкции он описан именно так.

## Решения

2026-10-13, по вопросам черновика.

1. **Отметки** — через `body` + `replaceBody`, без отдельной операции ядра.
2. **Пустые строки** — новый последний подзаголовок встаёт перед пустыми строками в конце родителя, для всех плагинов. `insertHeading` ядра уже так делает.
3. **Версия API** — 1.3.0, выпуск отдельно.
4. **Два PR:** A — операции, B — цели на них.

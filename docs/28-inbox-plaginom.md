# ТЗ: Inbox и его разбор — одним плагином

## Что делаем

Раздел Inbox в навигаторе и «Разбор Inbox» становятся одним встроенным плагином **«Inbox»** (`src/plugins/inbox`), включённым по умолчанию. В ядре остаются:
- **быстрый ввод** (⇧⌘I и окно быстрой записи) — стандартный Org: задача уходит в файл;
- **настройка «файл Inbox»** — без неё быстрому вводу некуда писать.

Почему один плагин, а не два: список и разбор работают с одним файлом, одним порогом «залежалась» и одним порядком задач. Разбор запускается из раздела, а его итог раздел сразу показывает. Два плагина не видят состояния друг друга (так задуман API), поэтому общее пришлось бы дублировать или выносить в ядро ради одной пары.

**Для пользователя ничего не меняется,** кроме места кнопки Inbox в навигаторе: она встаёт после разделов приложения, как у любого плагина (решение 4 к ТЗ 27). ⌃⌘2 остаётся за ней. e2e Inbox и разбора проходят без правок сценариев; правятся только порядок разделов и место хранения настроек.

## 1. Что из ядра нужно плагину (точки расширения, PR A)

| Что делает Inbox сейчас | Чего нет в API v1.1 | Предложение |
|---|---|---|
| Знает файл Inbox и следит за его сменой | Файл Inbox — настройка ядра | `index.inbox()` → `{ path }` и событие `inbox.changed` |
| Кнопки «Новая задача» (быстрый ввод), «Выбрать файл…», «Создать inbox.org» | Нет команд ядра | Команды ядра `capture.open`, `inbox.pickFile`, `inbox.createFile` |
| Число задач на кнопке раздела | Нет значка у раздела плагина | `ui.setBadge(navId, n)` |
| «Перенести…» — перенос ядра с плавным уходом строки, разбор знает, куда ушла задача | Нет переноса | `ui.refile(ref, { before? })` → `{ path, line, title, label } \| null` |
| Быстрые кнопки карточки: статус, дата, дедлайн, теги — палитра ядра | Есть только `heading.status` | Команды `heading.schedule`, `heading.deadline`, `heading.tags`, `heading.priority` |
| «Открыть в файле» — в соседнем редакторе, разбор остаётся впереди | `file.open` открывает здесь | `file.open { path, line, beside: true, focus: false }` |
| Тост «Отменить» после действия разбора | Нет отмены своего шага | `edit.undo()` — последний шаг журнала, если он плагина |
| Задачу правят прямо в карточке: строка и заголовок меняются | Ядро ищет карточку по заголовку | Ядро само следит за заголовком карточки при правке (как сейчас разбор Inbox) |
| Календарь под карточкой (⌘K): месяц записей календаря | Это часть календаря ядра | Виджет `month`: месяц записей с отмеченной задачей |
| Разбор целей и разбор Inbox — оба с ⌘1, ⌘2 | Одна область клавиш на все разборы плагинов: ложный конфликт | Своя область клавиш разбора у каждого плагина |

## 2. Настройки

Сейчас всё в `config.json` под ключом `inbox`. После переезда:
- **ядро:** файл Inbox и быстрый ввод (куда писать, клавиша, «в начало / в конец») — как сейчас, раздел «Настройки → Inbox»;
- **плагин:** порядок списка, число на кнопке, детали под заголовком, «залежалась через», порядок разбора, статусы «Выполнено» и «Отменить» — блоки «Список» и «Разбор» в том же разделе, по манифесту. Хранятся в папке заметок, как раньше. Варианты статусов плагин даёт через `settings.dynamic`.

Ядро один раз читает старые ключи `inbox.order`, `inbox.counter`, `inbox.details`, `inbox.stale`, `inbox.reviewOrder`, `inbox.reviewDone`, `inbox.reviewCancel` из `config.json`. Первое изменение пишет `.orgnotes/plugins/inbox.json` и убирает эти ключи из `config.json`. Файл Inbox и ключи быстрого ввода остаются на месте.

## 3. Перенос привычек

Ядро переносит сами:
- **сочетания:** `navInbox`, `review`, `reviewDone`, `reviewCancel`, `reviewMove`, `reviewDefer`, `reviewSkip`, `reviewBack`, `reviewCalendar` → `inbox.*`;
- **режим навигатора** `inbox` — id тот же;
- **вкладку** `review` — это сессия, не сохраняется.

## 5. Что выяснилось в PR B

- **Рамке разбора ядра не хватало пяти вещей.** Разбор Inbox держит свою очередь: пропущенная задача ждёт следующего прохода, «Назад» перескакивает удалённые, перенесённая задача остаётся в очереди в новом файле. Добавлено в API 1.2.0 (версия ещё не выпущена):
  - `next(cur, d)` — свой порядок карточек;
  - `bar`, `barEnd` — своя нижняя панель: «Отложить до…» раскрывается над кнопкой, как раньше;
  - `currentReview().show / setItems / end` — показать карточку, заменить очередь, закончить;
  - `onClose` — разбор закрыли;
  - `drawers` — ящики на карточке открыты.
- **Заголовок карточки следует только за правкой в самой карточке.** Правка извне (задачу удалили в другой программе) больше не подменяет карточку соседним заголовком.
- **Порядок разделов плагинов — как в списке плагинов:** «Цели», потом «Inbox».
- **Две области клавиш разборов плагинов не конфликтуют:** они не бывают открыты одновременно.

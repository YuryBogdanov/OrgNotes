## Контекст

После этапа 1 у нас есть API v1, загрузчик и права. Цели квартала по-прежнему — модуль ядра:
- `src/features/goals.svelte.ts` — 339 строк;
- `src/goals.ts` — 523 строки чистых функций;
- семь компонентов: `Goals`, `GoalsPanel`, `GoalForm`, `GoalAdd`, `GoalReview`, `GoalReport`, `GoalCarry`.

Они импортируют `store`, `layout`, `org`, `edits`, `textList`, `colors`. Берут из ядра компоненты `CardReview`, `NarrowEditor`, `PlacePicker`, `Calendar`, `ContextMenu`.

Задача пилота — перенести цели в `src/plugins/quarter-goals/` строго на публичном API. Всё, чего API не хватит, становится точкой расширения ядра, а не исключением для плагина.

**Для пользователя ничего не меняется:**
- раздел, обзор, «Мои цели», форма, отметки, разбор 1-1, отчёт и перенос квартала выглядят и работают как сейчас;
- e2e целей (`goals`, `goalReview`, `goalsReport`) проходят без правок сценариев, правятся только селекторы, если без этого никак;
- файлы целей остаются обычным Org.

## 2. Точки расширения ядра

### 2.1. Правка текста функцией и библиотека Org

- `tx.update(path, fn: (text: string) => string | null)` — правка файла функцией плагина внутри транзакции.
  - Сохранение, конфликты с диском и ⌘Z работают как у любой транзакции.
  - `null` — ничего не менять.
  - Нужно право `files.edit`.
  - Это для плагинов со своей структурой в файле (цели, шаблоны). Операции Org-уровня (§5.4 ТЗ 26) остаются основным путём.
- `@panopticon/api/org` — чистая библиотека Org без состояния ядра. Плагин включает её в свою сборку, поэтому она переживёт и будущую изоляцию.
  - Состав: разбор заголовков (`parseHeadings`), статусы, `setPlanning`, `setTags`, метки времени (`stamp(date, names)`, `weekdayNames(text)`), разбор даты по-русски (`parseDate`), правила списков «- » для многострочного ввода (`listEnter`, `listIndent`).
  - Код переезжает из `org.ts`, `edits.ts`, `textList.ts` или реэкспортируется оттуда; ядро пользуется тем же.
  - Тест границы разрешает импорт `@panopticon/api/org`.

### 2.2. Отмена с откатом состояния плагина

`edit.transaction(label, build, { onUndo })` — `onUndo` вызывается, когда шаг отменили: тостом «Отменить» или ⌘Z. Так разбор возвращает свои счётчики, как сейчас.

### 2.3. Разбор: что плагин может положить на карточку

`ReviewSpec` расширяется:
- `head?: Render<HeadingInfo>` — шапка карточки вместо строки: аватар, имя, «цель 2 из 5», плашка «молчит 21 день»;
- `quick?: Render<HeadingInfo>` — полоса быстрых кнопок под шапкой: «Статус», «Срок», «Квартал»;
- `aside?: Render<HeadingInfo>` — панель справа от суженного редактора: отметки и поле новой отметки;
- `narrow?: (h) => { fold?: number[]; note?: { line: number; text: string } }` — строки, свёрнутые в суженном редакторе («Отметки»), и подпись в конце строки («3 — справа»);
- `summary?: Render<ReviewResult>` — сводка вместо строки «Разобрано N из M»: три числа и кнопки «Открыть файл человека», «Закончить»;
- `actions[].disabled?: (h) => boolean` — «Добавить отметку» неактивна без текста, «Цель достигнута» — у закрытой цели.

Состояние разбора — очередь, черновик отметки, счётчики — плагин держит у себя. Ядро держит карточку, клавиши, «Назад» и суженный редактор.

### 2.4. Форма: многострочное поле, дата, своё поле

- `textarea` — многострочное поле, растёт по тексту. ↩ в списке «- » продолжает список, ⇥ сдвигает пункт — как сейчас в форме цели.
- `date` — дата. Вид `inline` — календарь на три месяца прямо в форме, как в форме цели. Вид `chip` — плашка, по клику открывается выбор даты.
- `custom` — поле, которое рисует плагин: `{ type: 'custom', key, label, render(el, value, set) }`. Это для «Чья цель» с аватаром и плашки квартала.
- `FormSpec.headerExtra?: Render` — место справа в заголовке листа («Квартал Q4 2026 ⌄»).

### 2.5. Выбор места

`pickPlace` получает:
- вид `columns` (как в «Добавить ещё цели»);
- `levels` (только 1-й уровень);
- `note(path)` — заметка у файла: «уже в целях», «3 цели»;
- `create: { label }` — строка «+ Создать «Квартальные задачи»». Если её выбрать, плагин получает `{ path, create: true }` и сам создаёт заголовок транзакцией.

### 2.6. Лист, меню, выбор из списка

- `ui.sheet({ title, render, buttons: [{ label, primary?, run }] }): Promise<void>` — лист ядра (затемнение, ⎋, фокус) с содержимым плагина. Для отчёта за квартал и переноса незакрытых.
- `ui.menu(items: { label, run, danger?, disabled? }[], at: { x, y })` — контекстное меню ядра.
- `ui.choose({ title, placeholder, items: { id, label, hint?, icon? }[] }): Promise<string | null>` — выбор из списка в палитре: «Чьи цели разобрать».

### 2.7. Мелочи

- `index.statusTone(keyword, path)` — именованный цвет статуса в наборах файла: `red`, …, `gray`. Плагин рисует через `var(--p-<цвет>)`, как ядро.
- `ctx.statusSets.set(defs)` — наборы статусов из кода; пустой массив убирает. Поле `statusSets` в манифесте остаётся для простых случаев.
- `navSections[].order` в манифесте — место в панели навигатора. Встроенный плагин может стоять между разделами ядра. У установленных место — только после разделов ядра.
- `ui.close(viewId)` — закрыть вкладки своего вида.
- Команда ядра `heading.status` {ref} — палитра статусов для заголовка, как «Сменить статус…» в редакторе.
- `commands.setAvailable(id, on)` — команда скрыта из палитры и не срабатывает по клавишам, пока недоступна.

## 3. Перенос данных и привычек

Плагин называется `quarter-goals`, имя для людей — «Цели квартала». Id `goals` занят ядром (0.6 и 1.2), поэтому всё со старым именем переносит ядро, один раз, при первом запуске версии с плагином:

- `.orgnotes/plugins/goals.json` `{ sources }` → `.orgnotes/plugins/quarter-goals.json` `{ data: { sources } }`. Старый файл удаляется после записи нового. Если в `config.json` ещё лежит ключ `goals` (до 0.6), он читается так же.
- `localStorage feature:goals` (пороги) → `feature:quarter-goals` `{ settings: { silent, soon } }`.
- Вкладки сохранённой раскладки: `goals` → `quarter-goals.overview`, `goalReview` закрывается (разбор — сессия).
- Сочетания, которые пользователь поменял: `navGoals`, `newGoal`, `goalsOverview`, `goalMark`, `goalDone`, `goalShift`, `goalBack`, `goalNext` → `quarter-goals.*`.
- Выбор раздела навигатора `goals` → `quarter-goals`.

Перенос покрывается e2e: старые файлы и настройки на входе, работающие цели на выходе.

## Открытые вопросы **[решить]**

1. **`tx.update(path, fn)` — правка файла целиком функцией плагина.** Это быстрый путь перенести цели как есть: их правки уже чистые функции над текстом. Альтернатива — переписать цели на операции Org-уровня (`insertHeading`, `replaceBody`, `move`). Это чище, но в два-три раза дороже и рискует поведением. Предлагаю `tx.update` и пометить его как «для своей структуры в файле».
2. **`@panopticon/api/org`** — делиться с плагинами разбором Org как библиотекой, а не через асинхронный `index`. Без неё цели не посчитать синхронно внутри `tx.update`. Предлагаю да.
3. **Цели включены по умолчанию?** В брифе цели — «отдельный плагин», ставится по желанию. Но сейчас ими пользуются, и после обновления раздел не должен пропасть. Предлагаю: встроенный и включён по умолчанию. Выключить можно в «Плагинах». При публикации (4.3) решим, остаётся ли он в поставке.
4. **Место раздела.** Встроенному плагину оставить «Цели» на прежнем месте (⌃⌘4 между «Агендой» и «Календарём»), установленным — только после разделов ядра. Согласны?
5. **Имя `quarter-goals`.** Как в брифе. Старые ключи переносит ядро один раз (§3).

# Как написать плагин для Panopticon

API плагинов **v1.2** (приложение 1.0 и новее). Подробности и решения — в ТЗ 26 и ТЗ 27, здесь — то, что нужно, чтобы написать и поставить плагин.

## Что такое плагин

Плагин — это папка с двумя файлами:

```
plugins/<id>/
  manifest.json   что плагин объявляет: команды и клавиши, раздел навигатора, вкладки, настройки, права
  main.js         его код: один ES-модуль, всё собрано внутрь, без импортов
```

Плагин работает внутри окна приложения. Видит он только объект `ctx` — API приложения. Писать в файлы он может только через транзакции, поэтому сохранение, конфликты с диском и ⌘Z работают как у правок руками.

Встроенные плагины лежат в `src/plugins/<id>/`: «Цели квартала», «Темы из Emacs», пример «Привет». Это хорошие образцы.

## Быстрый старт с шаблона

1. Скопируйте папку `templates/plugin/` из репозитория и переименуйте её: имя папки = `id` в `manifest.json`.
2. В `manifest.json` поменяйте `id` (латиница в нижнем регистре, цифры, дефис), `name` и ids команд: они начинаются с `<id>.`.
3. Соберите:
   ```bash
   npm install
   npm run build
   ```
   В папке `dist/` появятся `main.js` и `manifest.json`.
4. В приложении откройте «Настройки → Плагины → Открыть папку плагинов». Положите туда `dist` под именем `<id>`.
5. Нажмите «Перезагрузить плагины». Плагин появится в «Установленных» выключенным. Включите его: при первом включении приложение покажет, какие права он получит.

Поменяли код — соберите заново и снова нажмите «Перезагрузить плагины».

Шаблон написан на TypeScript и Svelte. Svelte не обязателен: можно рисовать обычным DOM, как в `src/plugins/hello`. Если пишете без сборки, `main.js` — это обычный модуль:

```js
export default {
  activate(ctx) {
    ctx.commands.on('my-plugin.hello', () => ctx.ui.notify('Привет!'));
  },
};
```

## manifest.json

```json
{
  "id": "my-plugin",
  "name": "Мой плагин",
  "version": "0.1.0",
  "description": "Что делает",
  "author": "Кто",
  "api": "^1.2",
  "minAppVersion": "1.0.0",
  "main": "main.js",
  "styles": "styles.css",
  "permissions": ["index.read", "files.edit", "clipboard", "net"],
  "net": ["jira.company.ru", "*.company.ru"],
  "contributes": {
    "commands": [
      { "id": "my-plugin.run", "title": "Мой плагин: сделать", "keys": ["⌃⌥⌘M"], "synonyms": ["слово"] },
      { "id": "my-plugin.pick", "title": "Мой плагин: выбрать…", "step": true },
      { "id": "my-plugin.ok", "title": "Разбор: Готово", "keys": ["⌘1"], "scope": "review" }
    ],
    "navSections": [{ "id": "my-plugin", "title": "Мой", "icon": "M4 4h12v12H4z", "key": "my-plugin.show" }],
    "views": [{ "id": "my-plugin.board", "title": "Доска", "icon": "M4 4h12v12H4z" }],
    "settings": [{ "section": "Мой плагин", "groups": [{ "caption": "ГЛАВНОЕ", "fields": [] }] }],
    "statusSets": [{ "name": "Идеи", "states": "IDEA DOING | DONE" }],
    "themes": ["themes/my-theme.json"]
  }
}
```

**Поля плагина:**

| Поле | Что это |
|---|---|
| `api` | Диапазон версий API: `^1.2`. Если API приложения не подходит, плагин не включится и покажет причину. |
| `minAppVersion` | Самая старая версия приложения, на которой плагин работает. |
| `main` | Файл кода; без него плагин — только данные (например, набор тем). |
| `styles` | Необязательный CSS: подключается тегом `<style>`. Можно не писать, если стили лежат в коде (так собирает шаблон). |
| `permissions` | Права: `index.read`, `index.touch`, `files.read`, `files.edit`, `clipboard`, `net` (см. «Права»). |
| `net` | Хосты для `net.fetch`: точный хост или `*.домен` для поддоменов. |
| `exports` | Имена функций, которые могут вызывать другие плагины (API 1.8). Сами функции плагин отдаёт через `ctx.exports`. |

**Вклады (`contributes`):**

| Вклад | Что это |
|---|---|
| `commands` | Команды: в палитре и в «Клавишах»; сочетания по умолчанию — `keys`. Занятые приложением (⌘S, ⌘W, ⌘Q, ⌘, ⌘Z, ⇧⌘Z) не назначаются. `"scope": "review"` — клавиша действия в разборе плагина; `"scope": "view"` — клавиша вида файла плагина (работает, пока вкладка показывает этот вид и фокус не в поле ввода; своя группа в «Клавишах», API 1.5). `"step": true` — команда из палитры сразу спрашивает выбор (`ui.choose`) следующим шагом той же палитры. `"note"` — серая строка под командой в «Клавишах» (API 1.6). |
| `navSections` | Раздел навигатора. Встаёт после разделов приложения. `key` — команда, которая его показывает. |
| `views` | Вкладки плагина. `"toolbar": true` — кнопка в группе «Открыть в панели», после кнопок приложения: вкладка во второй панели или убрать её. Новая вкладка получает `restore(null)`. |
| `fileViews` | Виды файла (API 1.5): `id`, `title`, `icon`, `key` — команда плагина, которая переключает вид. Появляются в меню вкладки файла «Показать как ›». |
| `fileTypes` | Свои типы файлов (API 1.10): `ext` — расширение без точки (латиница и цифры), `title`, `icon`, `view` — вид файла этого плагина, который их показывает, `template` — текст нового файла, `newLabel` — пункт меню папки («Новый холст»). Такие файлы видны в навигаторе со своей иконкой и без расширения, создаются из меню папки, переименовываются с сохранением расширения. Вкладка всегда показывает вид плагина, Org-редактор и «Показать как ›» для них не появляются. Плагин читает файл через `files.read` и пишет через `edit.transaction` → `tx.update(path, …)`. Сохранение, изменение на диске и ⌘Z работают как у заметок. У таких файлов нет заголовков: агенда, теги, поиск, перенос и мини-окно их не видят. Так «Холст» открывает `.canvas`. |
| `todayBlocks` | Блоки экрана «Сегодня» (API 1.4): `id`, `title`, `hint` (подсказка в «Настройки → Сегодня»), `"attach": true` — встаёт под предыдущим блоком в той же колонке. `"width": "full"` — блок во всю ширину, своей строкой; `"before"` / `"after"` — id блока, рядом с которым он встаёт при первом появлении (API 1.7). Порядок и включение задаёт пользователь. |
| `settings` | Разделы настроек (`section`) или блок в чужом разделе (`block: "Агенды"`). Поля: `choice`, `switch`, `text`, `file`, `pair`, `custom` (рисует плагин через `settings.dynamic(key, { render })`, API 1.12). У каждого поля есть `where`: `folder` — в папке заметок, едет с файлами; `local` — на этом Mac. |
| `statusSets` | Наборы статусов, пока плагин включён. Набор из кода — `ctx.statusSets.set`. |
| `themes` | Темы редактора в формате «своих тем» (экспорт из «Оформления»). |
| `slots` | Места в рисунке плагина, куда другие плагины кладут своё (API 1.8): `id`, `hint` — где это место и какие данные получает кусок. Плагин рисует их через `ui.drawSlot`, другие кладут через `ui.slot`. Календарь объявляет `calendar.weekCell`: у номера недели в месяце и у заголовка в виде «Неделя», данные `{ year, week, monday: "ГГГГ-ММ-ДД", view: "month" \| "week" }`. |

Ids команд, разделов, вкладок, блоков и мест начинаются с `<id>.` или равны `<id>`.

## Жизнь плагина

- **Включение.** Приложение регистрирует всё, что объявлено в манифесте, загружает `main.js` и вызывает `activate(ctx)`.
- **Ошибка.** Если `activate`, обработчик или отрисовка бросают ошибку, плагин выключается до перезапуска. Приложение показывает уведомление, а в «Плагинах» — «Выключен после ошибки» с текстом ошибки по «Подробнее». Остальные плагины работают.
- **Выключение.** Всё, что плагин зарегистрировал через `ctx`, снимается само, затем вызывается `deactivate()`. Вкладки плагина остаются в раскладке заглушкой с кнопкой «Включить».
- **Зависание** (бесконечный цикл) v1 не ловит: плагин работает в окне приложения.

## ctx — что умеет плагин

Все вызовы асинхронные или возвращают функцию снятия. Все данные — JSON, `HeadingRef` (`{ path, line, title }`, путь относительно папки заметок) и `Date`.

**Команды**

| Вызов | Что делает |
|---|---|
| `commands.on(id, run)` | Обработчик команды из манифеста. |
| `commands.setAvailable(id, on)` | Скрыть команду: её нет в палитре, клавиши не работают. |
| `commands.when(id, fn)` | Команда в палитре, только пока `fn()` возвращает `true`; спрашивается при открытии палитры. Например, «на заголовке долгого дела» по `ui.currentHeading()` (API 1.12). |
| `commands.keyOf(id)` | Текущее сочетание команды — для подсказок в интерфейсе плагина. |
| `commands.run(id, arg)` | Своя команда или команда приложения:<br>• `file.open {path, line?, beside?, focus?, neighbour?, newTab?}` — `beside` открывает в соседнем редакторе, текущая вкладка остаётся впереди; `neighbour` — как из агенды: в другой панели, если её нет — слева; `newTab` — в своей вкладке, показанная остаётся (API 1.12);<br>• `heading.reveal {ref}`;<br>• `file.reveal {path}` — показать файл в Finder (API 1.11);<br>• `heading.note {ref, x?, y?}` — поповер «Добавить заметку…» в точке окна (без `x, y` — вверху), заметку в `:LOGBOOK:` пишет ядро (API 1.12);<br>• `heading.status`, `heading.schedule`, `heading.deadline`, `heading.tags`, `heading.priority` `{ref}` — шаг палитры для заголовка, его файл должен быть открыт во вкладке;<br>• `agenda.open`;<br>• `capture.open` — быстрый ввод;<br>• `inbox.pickFile`, `inbox.createFile`;<br>• `settings.open {section?}` — настройки на разделе. |

**Интерфейс**

| Вызов | Что делает |
|---|---|
| `ui.navSection(id, render)` | Раздел навигатора. `render(el)` рисует в пустом элементе и возвращает функцию уборки. |
| `ui.view(id, { title, crumbs?, restore?, render, inspector? })` | Вид вкладки. `render(el, state, tab)`; `tab.setState(s)` сохраняет состояние вместе с раскладкой. `inspector(el, state, tab)` — свой инспектор справа, пока вкладка активна; перерисовывается, когда меняется её состояние. |
| `ui.open(viewId, state, 'here' \| 'beside')`, `ui.close(viewId)` | Открыть вкладку плагина (в этом или соседнем редакторе) и закрыть его вкладки. |
| `ui.menu(items, at)` | Контекстное меню приложения. У пункта может быть `checked` (галочка) и `hint` (серая строка под ним, API 1.5). |
| `ui.notify(text, actions?)` | Уведомление внизу окна, с кнопками. |
| `ui.setBadge(navId, n, { tone? })` | Число на кнопке раздела навигатора. `tone: 'alert'` (API 1.13) — «тревожное» число: в сайдбаре нового интерфейса оно красное, например «пора проверить»; старый навигатор рисует его как обычное. |
| `ui.fileView(id, { render, defaultFor? })` | Вид файла из `fileViews` (API 1.5): вкладка файла показывает его вместо текста. `render(el, { path }, { showText })`; `defaultFor(text)` — файл, открытый впервые, показывается так (у канбана — когда есть `#+BOARD`). Вид запоминается для каждого файла. Во вкладке одной ветки (API 1.9) приходит ещё `heading`, а `view.setHeading(ref)` сообщает, что заголовок ветки переименован или сдвинулся: имя вкладки следует за ним. |
| `ui.showAs(viewId \| null)` | Вкладка файла переходит на вид плагина или на текст (`null`). |
| `ui.openFileView(viewId, { path, heading? }, where?)` | Файл в виде плагина в своей вкладке (API 1.9): весь файл или — с `heading` — одна ветка. Вкладка называется «файл › заголовок», «Текст» открывает файл на этом заголовке. Если такая ветка в этом виде уже открыта, показывается её вкладка. `false` — нет файла или заголовка. Так «Холст» показывает ветку как mindmap. |
| `ui.currentHeading()` | Заголовок, на котором пользователь (API 1.9): под кареткой в редакторе или ветка вкладки вида на одном заголовке; `null` — нет. |
| `ui.headingAction({ label, when?, run })` | Пункт меню заголовка (API 1.9): в структуре навигатора и в редакторе на строке заголовка. `when(heading)` решает, к каким заголовкам он относится; `run(ref)` — что делает. |
| `ui.saveFile({ name, title?, filter?, text? \| base64? })` | Системное окно «Сохранить как…» для экспорта (API 1.11): `name` — предложенное имя, `filter` — `{ name, extensions }`, содержимое — текстом или байтами в base64 (картинка). Возвращает путь, куда записано, или `null`, если отменено. Место выбирает пользователь, права не нужны. Так «Холст» сохраняет `.excalidraw`, PNG и SVG. |
| `ui.editor(el, ref, { onRef? })` | Заголовок с поддеревом в суженном редакторе в элементе плагина (API 1.5): правки сразу в файле, Org-клавиши работают. `onRef(ref)` — где заголовок сейчас. Возвращает `{ focus, dispose }`. Так сделана карточка сбоку на доске. |
| `ui.editorLink({ label, run })` | Серая ссылка в конце строк редактора: `label(text, line)` — текст ссылки или `null`, `run(path, line)` — клик. Файл не меняется. |
| `ui.taskList(el, spec)` | Список задач плагина (API 1.6), например карточки доски. Пока фокус в `el`, на выбранной задаче работают клавиши группы «Задачи в списках», группа палитры «Выделенная задача» и инспектор.<br>`spec`:<br>• `selected()` — `{ ref, date? }` или `null`;<br>• `open(other)` — ↩ / ⌥↩;<br>• `clear()` — ⎋;<br>• `refresh?()` — ⌘R;<br>• `otherLabel?` — название второго пункта меню;<br>• `more?(ref)` — свои пункты в конце меню.<br>Возвращает `{ menu(at), dispose }`: `menu` показывает общее меню задачи (статус, приоритет, даты, теги, перенос, ссылка, действия плагинов). |
| `ui.slot(id, render)` | Свой кусок в месте другого плагина (`slots` его манифеста), API 1.8. `render(el, data)` вызывается для каждого элемента этого места: например, для каждой недели в календаре. Возвращает функцию уборки. |
| `ui.drawSlot(el, id, data)` | Нарисовать в `el` куски, которые плагины положили в своё место (API 1.8). У каждого куска свой `div` с `display: contents`. Куски перерисовываются, когда плагин включают или выключают. Возвращает `{ update(data), dispose() }`. |
| `ui.taskAction({ label, when?, run })` | «Действие с задачей» (API 1.6): пункт меню задачи во всех списках и команда группы «Выделенная задача» в палитре. `when(heading)` решает, к каким задачам оно относится; `run(ref)` — что делает. Так цели квартала добавляют «Добавить отметку…». |
| `ui.todayBlock(id, render)` | Блок экрана «Сегодня» из `todayBlocks` (API 1.4). Приложение рисует карточку, плагин — её содержимое: `render(el, block)`. `block.setHidden(true)` убирает блок, пока показать нечего; соседние занимают место. |
| `ui.oneOnOne({ line?, action? })` | Что плагин добавляет в карточку «1-1 сегодня» (API 1.4): `line(path)` — строка под человеком, `action` — кнопка `{ label, available?(path), run(path) }`. `path` — файл человека относительно папки. Так «Цели квартала» показывают цели и «Разбор целей». |
| `ui.setMonthFilter({ layers, hidden } \| null)` | Что показывает месяц приложения под карточкой разбора (виджет `month`): слои записей и скрытые файлы. Так календарь передаёт свой выбор. |
| `ui.refile(ref, { before?, quiet?, onUndo? })` | Перенос заголовка приложения («Перенести в…»). Возвращает, куда ушёл заголовок, или `null`, если отменили. `onUndo` — перенос отменили (⌘Z, «Отменить»). |
| `ui.form({ title, groups, submit, validate?, onChange?, headerExtra? })` | Лист с полями. Поля — те же, что в настройках, плюс: `textarea` (списки «- »), `date` (`inline` \| `chip`), `place` (файл и заголовок колонками, `create`), `custom` (рисует плагин). У текстового поля `suggest(q, values)` (API 1.14) — подсказки к набранному: `{ value, hint? }[]`; в новом интерфейсе они в поповере под полем, в старом — чипами под ним. |
| `ui.sheet({ title, render, buttons? })` | Лист с содержимым плагина. С `bare: true` плагин рисует весь диалог сам. |
| `ui.menu(items, {x, y})` | Контекстное меню; `'sep'` — разделитель. |
| `ui.choose({ title, items })` | Выбор из списка в палитре. |
| `ui.pickPlace({ kind?, levels? })` | Выбор «файл + заголовок». |
| `ui.pickDate({ initial?, kind?, names?, current? })` | Календарь на три месяца. |
| `ui.widget(el, field, value, onChange)` | Календарь, выбор места, поле со списками или месяц записей календаря (`month`) приложения внутри элемента плагина. |
| `ui.review(spec)` | Разбор карточками: по одному заголовку, суженный редактор, действия на клавишах команд с `scope: review`. Плагин может:<br>• нарисовать шапку, быстрые кнопки, панель справа, сводку (`head`, `quick`, `aside`, `summary`);<br>• свернуть строки (`narrow`);<br>• сохранить ввод перед сменой карточки (`beforeStep`).<br>Свой порядок и своя нижняя панель (так сделан «Разбор Inbox»):<br>• `bar`, `barEnd` — кнопки внизу рисует плагин, действия остаются на клавишах;<br>• `next(cur, d)` — какая карточка следующая;<br>• `onClose` — разбор закрыли;<br>• `drawers: true` — ящики (`:PROPERTIES:`) открыты.<br>Заголовок карточки можно править прямо в ней. Клавиши разбора у каждого плагина свои. `ui.currentReview()` → `step`, `redraw`, `update`, `show(i)`, `setItems(refs, cur?)`, `end()`. |

**Данные**

| Вызов | Что делает |
|---|---|
| `index.query({ conds, sources?, sort? })` | Заголовки с задачами — тот же движок, что у агенды. Условия как в конструкторе агенды. |
| `index.heading(ref)`, `index.outline(path)`, `index.files()` | Один заголовок, заголовки файла, файлы папки. В `HeadingInfo` с API 1.7 есть `properties` (свойства своего ящика, ключи заглавными) и `event` — встреча: активная дата строкой под заголовком, а если её нет — в названии. |
| `index.byId(id)` | Заголовок с таким `:ID:` в любом файле папки, `null` — нет (API 1.10). |
| `index.body(ref)` | Текст заголовка без его подзаголовков, планирования и ящиков (API 1.7). |
| `index.workflow(path)`, `index.statusTone(keyword, path)` | Статусы файла и его наборы (`sets`); цвет статуса — рисуйте через `var(--p-<цвет>)`. `logbook` (API 1.8) — ведётся ли журнал: смены статусов и переносы дат пишутся в `:LOGBOOK:`. |
| `HeadingInfo.reschedules` | Переносы `SCHEDULED` из `:LOGBOOK:` заголовка (API 1.8): `{ from, at }` — с какого дня и когда перенесли. Пока ведётся журнал, приложение пишет их так же, как Emacs (`- Rescheduled from "<…>" on […]`). |
| `HeadingInfo.touched`, `index.touched(ref)` | Касание (API 1.12): когда в последний раз менялся заголовок вместе с подзаголовками — `{ at, approx }`. `approx` — дата взята из файла, истории ещё нет (последняя запись `:LOGBOOK:`, CLOSED или время изменения файла); показывайте её со знаком «≈»; `src` — откуда она: `logbook`, `closed` или `file`. Перенос заголовка без правки текста, пробелы и пустые строки, переименование тега или статуса во всех файлах касанием не считаются. Пока индекс строится, касания нет. |
| `index.lastNote(ref)` | Последняя заметка из `:LOGBOOK:` самого заголовка (без подзаголовков): записанная по `C-c C-z` или текст после смены статуса (API 1.12). `{ at, text }`, `null` — заметок нет. |
| `index.markReviewed(ref)` | «Осмотрено» (API 1.12): касание без правки файла. Нужно право `index.touch`. |
| `index.inbox()` | Файл Inbox (настройка приложения; туда пишет быстрый ввод): `path`, `chosen` — что выбрано, если файла нет, `add` — новые задачи в начало или в конец. |
| `index.folder()` | Рабочая папка (путь на этом Mac): то, что плагин хранит на Mac отдельно для каждой папки. |
| `files.read(path)` | Текст файла папки заметок. |
| `edit.undo()` | Отменить последний шаг журнала (кнопка «Отменить» в уведомлении). |
| `edit.ensureFile(path)` | Файл папки; если его нет — создаётся пустым (архив `<файл>_archive`, API 1.5). |
| `edit.transaction(label, tx => …, { onUndo?, touch? })` | Одна правка — один шаг ⌘Z. `touch: false` (API 1.12) — массовая правка по многим файлам (переименование): заголовки, которые она меняет, не получают касания. Операции идут по порядку, и каждая видит результат предыдущих:<br>• `setStatus`, `setPlanning`, `setTags`, `setProperty`, `replaceBody`, `move`, `remove`, `setTitle` (новое название, звёзды, статус, приоритет и теги остаются; API 1.7);<br>• `insertHeading` — возвращает ссылку на созданный заголовок; место — первым или последним под заголовком, перед его подзаголовком (`{ under, before }`), в начале или в конце файла, сразу после поддерева другого заголовка на его уровне (`{ after }`, API 1.5);<br>• `move` — под заголовок, на верхний уровень файла или рядом с другим заголовком того же файла (`{ before }` / `{ after }`, API 1.5);<br>• `ensureChild(under, title, { before? })` — найти подзаголовок по названию или создать его;<br>• чтение: `heading`, `children`, `body`;<br>• `update(path, text => …)` — запасной путь: своя функция над текстом файла, для своей структуры в файле (и единственный способ записать файл своего типа, `fileTypes`);<br>• `ensureId(ref)` — `:ID:` заголовка; если его нет, записывается новый UUID (API 1.10). На него держится ссылка или карточка на холсте;<br>• `addNote(ref, text)` — заметка первой строкой `:LOGBOOK:` заголовка, как пишет Emacs по `C-c C-z`: `- Note taken on [дата] \\` и текст под ней. Ящика нет — создаётся после свойств или планирования (API 1.12). |
| `exports({ имя: функция })` | Отдать другим плагинам функции из `exports` манифеста (API 1.8). |
| `plugins.call(id, fn, ...args)` | Вызвать функцию другого плагина (API 1.8). Аргументы и результат копируются как данные. Если плагин выключен, не установлен или такой функции не отдаёт — `undefined`. Пример: `plugins.call('quarter-goals', 'myActiveGoals')` возвращает активные цели «Мои» текущего квартала: `{ title, ref, deadline }`. |
| `storage.folder`, `storage.local` | Свои данные: `get`, `set`, `onChange`. В папке заметок — `.orgnotes/plugins/<id>.json`; на этом Mac — локально. |
| `settings.values()`, `settings.onChange`, `settings.dynamic(key, { options?, hint?, show?, clean?, render? })` | Значения настроек из манифеста; варианты (у `pair` — оба списка) и подсказки, которые зависят от значений; как показать выбранный файл; как привести введённый текст; `render(el, ctrl)` рисует поле `custom` во всю ширину раздела, значение — через `ctrl.value()` и `ctrl.set()` (API 1.12). |
| `statusSets.set(defs, { ifMissing? })` | Наборы статусов из кода. |
| `events.on(...)` | События: `file.changed {path, by}`, `heading.changed`, `heading.touched {ref, at}` (касание или «Осмотрено», пачками не чаще раза в секунду; API 1.12), `tab.active {kind, path, state}`, `folder.changed`, `inbox.changed {path}`, `day.changed`, `theme.changed`. |

## Права

| Право | Что даёт |
|---|---|
| `index.read` | `ctx.index`. |
| `index.touch` | `ctx.index.markReviewed` — отметить дело осмотренным (API 1.12). |
| `files.read` | `ctx.files`. |
| `files.edit` | `ctx.files` и `ctx.edit`. |
| `clipboard` | `ctx.clipboard.write`. |
| `net` | `ctx.net.fetch` — только к хостам из `net`. Ответ до 10 МБ, таймаут 30 с. |

- Без права нужного поля в `ctx` нет — проверяйте: `if (ctx.net) …`.
- Прямой `fetch` из окна закрыт.
- Права защищают от ошибок, но не от намеренно вредного кода. Поэтому при первом включении и при изменении прав приложение спрашивает пользователя.

## Вид

Рисуйте цветами приложения, тогда плагин следует теме и оформлению:
- текст и фон — `--fg`, `--fg2`, `--fg3`, `--bg`;
- линии и поля — `--line`, `--field`, `--side`;
- акцент — `--acc`, `--onacc`;
- восемь именованных цветов темы — `--p-red`, `--p-orange`, `--p-yellow`, `--p-green`, `--p-teal`, `--p-blue`, `--p-purple`, `--p-gray`.

### В новом интерфейсе (бета)

В новом интерфейсе панели и вкладки плагина рисуются внутри слоя совместимости. Эти же переменные там получают цвета нового интерфейса: фон «бумаги», текст «синьки», акцент — лампа (`--acc` для текста и рамок, `--pacc` для кнопок с заливкой), именованные цвета — из темы «Синька». Раскладка и шрифты плагина остаются его собственными. Если рисовать цветами из списка выше, менять ничего не нужно.

Элемент слоя помечен атрибутом `data-ui="next"`. Плагин может по нему подстроиться, например:

```css
[data-ui="next"] .my-card { border-radius: 10px; }
```

или в коде — `el.closest('[data-ui="next"]')`. Своих цветов вместо переменных лучше не задавать: в новом интерфейсе они окажутся «чужими».

## Отладка

- «Настройки → Плагины → Перезагрузить плагины» перечитывает папку и запускает включённые плагины заново, ошибки сбрасываются.
- Ошибку плагина видно в «Подробнее» и в консоли веб-инспектора (`plugin <id>: …`).
- Чтобы проверить права, отключите лишние в манифесте: поля `ctx` пропадут.

## Публикация

Установленный плагин помнит, откуда он: рядом с ним лежит `.source.json`. По нему «Настройки → Плагины» показывают источник и проверяют обновления раз в сутки. Есть два пути.

**Каталог** — [Panopticon-Org-Notes/plugins](https://github.com/Panopticon-Org-Notes/plugins), как в Obsidian:

- репозиторий плагина публичный, в его ветке по умолчанию лежит `manifest.json`. По нему приложение узнаёт последнюю версию, права и совместимость;
- каждая версия — релиз GitHub с тегом `1.2.0` или `v1.2.0`, равным `version` манифеста, с ассетами `manifest.json`, `main.js` и, если нужен, `styles.css`. В шаблоне это делает `.github/workflows/release.yml`: поставьте тег, и релиз соберётся сам;
- в каталог плагин попадает через PR с записью в `plugins.json` (правила — в README каталога).

**По ссылке на git** — для плагинов организации в приватных хранилищах (GitLab, Gitea, Bitbucket, GitHub):

- приложение клонирует нужный тег или ветку системным `git` с ключами этого Mac. Ничего не собирает и не запускает;
- в теге или ветке должны лежать собранные `manifest.json` и `main.js` (и `styles.css`) — в корне или в `dist/`. То есть `dist/` коммитится в теги релизов;
- обновления — новый тег с версией больше установленной или новый коммит отслеживаемой ветки.

**Обновление:**

- если права не изменились — приложение просто ставит новую версию и перезапускает только этот плагин;
- если изменились — сначала спрашивает их.

**Удаление** уносит папку плагина в Корзину. Его данные (`storage`, настройки) остаются.

## Перетаскивание в вид плагина

С API 1.10 списки приложения отдают перетаскиваемое под типом `DRAG_TYPE` (`application/x-panopticon`): заголовки — из структуры навигатора, «Структуры», агенды, поиска и вкладки «Тег»; файлы — из навигатора. Плагин читает это в своём элементе функцией `droppedOf(e.dataTransfer)` из `@panopticon/api`: `{ kind: 'heading', ref, id? }` (`id` — `:ID:`, если он есть) или `{ kind: 'file', path }`. Пока объект тащат над элементом, данные ещё не прочитать: `draggingOurs(e.dataTransfer)` говорит, что тащат объект приложения (вызовите `preventDefault()` в `dragover`, чтобы разрешить сброс).

## Чего пока нет

- **Библиотека Org** (`@panopticon/api/org`) есть только у встроенных плагинов. Сторонним её пока не дать без исходников приложения; задача — в роадмапе.
- **Изоляции кода и защиты от зависаний** нет (API v2).
- **Декораций редактора** нет: подсветки и значков в тексте.

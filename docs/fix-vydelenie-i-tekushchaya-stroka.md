# Багфикс: выделение текста сливается с подсветкой текущей строки

2026-10-12 · Yury Bogdanov

## Симптом

В редакторе на текущей строке (где курсор) выделенный текст почти или совсем не виден. В многострочном выделении строки выше и ниже выглядят выделенными, а строка с курсором — нет. Особенно заметно в светлой теме.

## Причина

`app.css`:

```css
.cm-editor .cm-activeLine { background: var(--cur); }            /* #eef4ff / #2a3347 — непрозрачные */
.cm-editor .cm-selectionBackground, .cm-editor.cm-focused .cm-selectionBackground { background: var(--sel) !important; }
```

1. **Подсветка строки закрывает выделение.** С `drawSelection()` CodeMirror рисует выделение отдельным слоем *под* текстом. Фон `.cm-activeLine` лежит на элементе строки, то есть *над* слоем выделения. Пока `--cur` непрозрачный (`#eef4ff` в светлой теме, `#2a3347` в тёмной), он закрывает выделение на текущей строке. Поэтому в стандартной теме CodeMirror у active line полупрозрачный фон.
2. **Цвета слишком близки.** Даже там, где выделение просвечивает, оба цвета — бледно-голубые: `--cur` ≈ `#eef4ff`, `--sel` (14% синего) ≈ `#e0ecfa`. На глаз разницы почти нет.
3. **Нет состояния «без фокуса».** Выделение в неактивной панели выглядит так же, как в активной.

## Что сделать

**1. Отдельные токены для редактора, полупрозрачные.** `--cur` и `--sel` используются и в других местах (списки, навигатор), их не трогаем. Для редактора заводим свои:

| Токен | Светлая | Тёмная | Где |
| --- | --- | --- | --- |
| `--cur-line` | `rgba(10,100,214,0.05)` | `rgba(108,180,255,0.07)` | фон текущей строки и её номера |
| `--sel-text` | `rgba(10,100,214,0.26)` | `rgba(10,132,255,0.45)` | выделение в редакторе в фокусе |
| `--sel-text-blur` | `rgba(0,0,0,0.10)` | `rgba(255,255,255,0.14)` | выделение, когда панель не в фокусе (серое, как в macOS) |

```css
.cm-editor .cm-activeLine { background: var(--cur-line); }
.cm-editor .cm-activeLineGutter { background: var(--cur-line) !important; color: var(--fg); }
.cm-editor .cm-selectionBackground { background: var(--sel-text-blur) !important; }
.cm-editor.cm-focused .cm-selectionBackground { background: var(--sel-text) !important; }
```

**2. Пока есть выделение, текущая строка не подсвечивается.** Если выделение непустое, подсветка строки только мешает. Небольшой `ViewPlugin` ставит на `.cm-editor` класс `cm-has-selection`, когда `!state.selection.main.empty`:

```css
.cm-editor.cm-has-selection .cm-activeLine,
.cm-editor.cm-has-selection .cm-activeLineGutter { background: transparent !important; }
```

**3. Проверить пересечения с другими подсветками** — они не должны прятать выделение и не должны прятаться под ним:

- совпадения поиска (`findView.ts`, токены `hl` / `hlCur`, ТЗ 21): текущее совпадение после ⌘G одновременно выделено. Выделение должно быть видно поверх жёлтого или совпадать с ним по рамке; жёлтый не должен перекрывать выделение на других строках;
- строка, раскрытая под курсором в «Оформленном тексте» (ТЗ 19), — у неё тоже фон текущей строки;
- подсветка текущей строки в макетах (`#eef4ff` / `#2a3347`) остаётся как ориентир по виду: полупрозрачный `--cur-line` на белом фоне даёт примерно тот же цвет.

## Приёмка

- В обеих темах выделение одной строки, нескольких строк и строки с курсором хорошо видно. Строка с курсором не выглядит «дырой» в многострочном выделении.
- Без выделения текущая строка подсвечена так же мягко, как сейчас.
- При непустом выделении подсветка текущей строки и её номера исчезает.
- В неактивной панели выделение серое, в активной — синее.
- Выделение видно поверх совпадений поиска и в режиме «Оформление».
- e2e: скриншоты светлой и тёмной темы с многострочным выделением, проходящим через строку курсора; проверка класса `cm-has-selection`.
